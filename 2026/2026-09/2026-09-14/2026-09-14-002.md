### Step 1: Find the Exact Reason in the Hyper-V Event Log

Hyper-V always logs the underlying Win32 cause (e.g. file missing, access
denied) to the event log. In an **Elevated ( Administrator)** PowerShell window,
run:

```powershell
Get-WinEvent -LogName 'Microsoft-Windows-Hyper-V-VMMS-Admin' -MaxEvents 20 |
        Where-Object { $_.Message -match 'se\.windows' -or $_.Message -match 'Export' } |
        Format-List TimeCreated, Message
```

### Step 2: Most Common Causes and Fixes

#### 1. Attached ISO in Virtual DVD Drive (_Most common for Windows VMs_)

Windows VMs frequently retain an ISO attached to their virtual DVD drive (e.g.
Windows Setup, VirtIO, or tools ISO). If that ISO was moved, deleted, resides on
a temp path, or Hyper-V's service cannot access it, `Export-VM` aborts with
`0x80004005`.

**Check & Eject:**

```powershell
# Inspect the drive:
Get-VMDvdDrive -VMName "se.windows.hyperv.zeus.df.io"

# Unmount / eject any ISO:
Set-VMDvdDrive -VMName "se.windows.hyperv.zeus.df.io" -Path $null
```

#### 2. Leftover Empty Backup Directory

When the export failed, Hyper-V left behind the target directory:
`D:\var\hyper\backup\se.windows.hyperv.zeus.df.io` _(currently empty: 0 files)_.

Hyper-V **refuses to export** into a directory that already exists. Before
retrying, delete it:

```powershell
Remove-Item -Path "D:\var\hyper\backup\se.windows.hyperv.zeus.df.io" -Recurse -Force
```

#### 3. Orphaned or Inconsistent Checkpoints

`se.windows` has checkpoints in `D:\var\hyper\se\checkpoints\Snapshots`. If an
`.avhdx` differencing disk or snapshot configuration has a broken link:

```powershell
# List existing checkpoints:
Get-VMSnapshot -VMName "se.windows.hyperv.zeus.df.io"

# If not needed, remove/merge them before export:
Get-VMSnapshot -VMName "se.windows.hyperv.zeus.df.io" | Remove-VMSnapshot
```

#### 4. Virtual Machine Service SID Permissions

If disks were moved manually, verify `NT VIRTUAL MACHINE\Virtual Machines` has
read permissions on all disk and configuration directories.

### Step 3: Run the Export Again for Just `se.windows`

Once the ISO is ejected and the empty destination folder is cleaned up:

```powershell
Export-VM -Name "se.windows.hyperv.zeus.df.io" -Path "D:\var\hyper\backup"
```

### Critical Fix Needed in [

`hyperv.ps1`](file:///C:/usr/src/df/powershell/df-powershell/devops/zeus/hyperv/hyperv.ps1#L133-L136)

Notice in your output:

```text
Export-VM : Export failed for virtual machine 'se.windows.hyperv.zeus.df.io'... (0x80004005).
Export completed: se.windows.hyperv.zeus.df.io
```

Because `Export-VM` emits a non-terminating error by default, the script
continued to line 135 and printed `Export completed: se.windows...`. If you had
proceeded to `-PurgeAll`, **the VM would have been permanently deleted without a
valid backup**.

To fix lines 133–136 in
[ `hyperv.ps1`](file:///C:/usr/src/df/powershell/df-powershell/devops/zeus/hyperv/hyperv.ps1#L133-L136):

```powershell
        Write-Host "Exporting VM '$name' to '$BackupRoot'..." -ForegroundColor Cyan
        try
        {
            Export-VM -Name $name -Path $BackupRoot -ErrorAction Stop
            Write-Host "Export completed: $name" -ForegroundColor Green
        }
        catch
        {
            Write-Error "Export failed for '$name': $( $_.Exception.Message )"
            # Clean up partial directory to prevent locking future retries
            $failedDir = Join-Path $BackupRoot $name
            if ((Test-Path $failedDir) -and (Get-ChildItem -Path $failedDir -Recurse -File).Count -eq 0)
            {
                Remove-Item -Path $failedDir -Recurse -Force
            }
        }
```
