# 2026-09-17-001

## Summary

Hyper-V allows multiple virtual machines to share the exact same display name as
long as their internal GUIDs (`VMId`) differ. Having two VMs with the same name
caused `Get-VM -Name ...` to return both, leading `Export-VM` to fail (or target
the faulty one).

The faulty VM's ID from your earlier error log is
**`A731E1CB-2F65-4C08-99BB-A07C237E0FFF`**.

Here is how to identify them, remove the faulty one, and rerun the backup:

---

### Step 1: Confirm Both VMs

Run this in your elevated prompt to inspect both:

```powershell
Get-VM -Name "se.windows.hyperv.zeus.df.io" | Select-Object Id, Name, State, CreationTime, @{ N = "Checkpoints"; E = { (Get-VMSnapshot -VM $_).Count } }, @{ N = "Disks"; E = { (Get-VMHardDiskDrive -VM $_).Path } } | Format-List
```

You will see:

- **Faulty old VM**: ID `A731E1CB-2F65-4C08-99BB-A07C237E0FFF` (has
  checkpoints).
- **Clean new VM**: Has a new GUID, 0 checkpoints, and points directly to
  [ `se-disk-001.vhdx`](file:///C:/var/hyperv/se/virtual-hard-disks/se-disk-001.vhdx).

---

### Step 2: Remove the Faulty Old VM by its GUID

Remove only the old registration using its exact GUID (this will **not** touch
your `.vhdx` file):

```powershell
Get-VM -Id "A731E1CB-2F65-4C08-99BB-A07C237E0FFF" | Remove-VM -Force
```

---

### Step 3: Clean up any Leftover Backup Directory

If the failed attempt left an empty folder in your backup destination, clear it:

```powershell
if (Test-Path "D:\var\hyper\backup\se.windows.hyperv.zeus.df.io")
{
    Remove-Item "D:\var\hyper\backup\se.windows.hyperv.zeus.df.io" -Recurse -Force
}
```

---

### Step 4: Verify Only One VM Remains

```powershell
Get-VM -Name "se.windows.hyperv.zeus.df.io" | Select-Object Id, Name, State, @{ N = "Checkpoints"; E = { (Get-VMSnapshot -VM $_).Count } }
```

_(Should return exactly 1 VM with 0 checkpoints)_

---

### Step 5: Run the Backup

```powershell
.\hyperv.ps1 -Backup -VMNames "se.windows.hyperv.zeus.df.io" -BackupRoot "D:\var\hyper\backup"
```
