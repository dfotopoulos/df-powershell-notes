### 1. Do you need to back up settings separately?

**Short answer: No, but saving a lightweight JSON spec is highly recommended.**

- **What `Export-VM` already backed up:** The `Virtual Machines` folder in each
  backup contains the complete binary configuration (`.vmcx` and `.vmgs`). This
  stores all VM hardware settings (Generation, vCPUs, RAM, Dynamic Memory,
  Secure Boot, TPM keys, MAC addresses, and disk controllers).
- **The one thing not in `.vmcx`:** The **Virtual Switch** on the host. When
  restoring to the same or a new machine, Hyper-V needs to know which virtual
  switch to attach the network adapter to.
- **Best Practice:** Dump a human-readable JSON spec file into
  `D:\var\hyper\backup\` before purging. It takes a few kilobytes and serves as
  permanent documentation:

```powershell
Get-VM -Name "bookworm.debian.hyperv.zeus.df.io","production.freebsd.hyperv.zeus.df.io","se.windows.hyperv.zeus.df.io" |
        Select-Object Name, Generation, ProcessorCount, MemoryStartup, DynamicMemoryEnabled, MemoryMinimum, MemoryMaximum,
        @{ N = "SwitchName"; E = { (Get-VMNetworkAdapter -VM $_).SwitchName } },
        @{ N = "SecureBoot"; E = { (Get-VMFirmware -VM $_ -ErrorAction SilentlyContinue).SecureBoot } },
        @{ N = "VhdPath"; E = { (Get-VMHardDiskDrive -VM $_).Path } } |
        ConvertTo-Json -Depth 3 | Set-Content "D:\var\hyper\backup\vm-specs.json"
```

### 2. Is it better to purge the disks and use a script to reintroduce them later?

**Yes, that is the cleanest operational model**, especially since purging the
host disks will reclaim **~330 GB on your `C:\` drive** (which previously had
only ~66 GB free).

Because `Export-VM` backed up both the `.vhdx` and `.vmcx`, you actually have
two reintroduction options in the future:

1. **Built-in `hyperv.ps1` Restore (Uses `.vmcx`)**:
    - Run directly off `D:\` without copying to `C:\`:
        ```powershell
        .\hyperv.ps1 -RestoreInPlace -BackupRoot "D:\var\hyper\backup" -VMNames "se.windows.hyperv.zeus.df.io"
        ```
    - Copy back onto `C:\`:
        ```powershell
        .\hyperv.ps1 -RestoreCopy -BackupRoot "D:\var\hyper\backup" -VMNames "se.windows.hyperv.zeus.df.io" -RestoreDestination "C:\var\hyperv\se"
        ```

2. **Declarative Reintroduction Script (Infrastructure-as-Code)**: If you ever
   restore onto a newer Windows version or want to guarantee **zero checkpoint
   ghosts or GUID conflicts**, a declarative PowerShell script that takes the
   `.vhdx` and attaches it to a freshly defined VM is the cleanest approach.
