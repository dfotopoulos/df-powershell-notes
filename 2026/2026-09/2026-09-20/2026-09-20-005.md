# 2026-09-20-005

## Summary

### What Happened

1. **User and Group Membership Succeeded:** The user account `df` was **already
   successfully created** and **added to the `Administrators` group**:

    ```text
    [INFO] Creating local user 'df' (Dimitrios Fotopoulos)...
    [INFO] Adding 'df' to administrative group 'Administrators'...
    [SUCCESS] User 'df' (Dimitrios Fotopoulos) is now a full local Administrator!
    ```

2. **The Cause of the Summary Error:** The error occurred during the final step
   when rendering the summary card:
    - In `Microsoft.PowerShell.LocalAccounts`, `LocalUser` objects do not have
      properties named `PasswordNeverExpires` or `AccountNeverExpires` (those
      are only parameter names for `New-LocalUser`).
    - The actual object properties are `PasswordExpires` and `AccountExpires`
      (which evaluate to `$null` when the account/password never expires).
    - Under `Set-StrictMode -Version Latest`, referencing
      `$newUser.PasswordNeverExpires` threw:
        ```text
        The property 'PasswordNeverExpires' cannot be found on this object. Verify that the property exists.
        ```
    - Because the summary output was inside the same `try/catch` block, it
      falsely reported: `Failed to add 'df' to the Administrators group`.

---

### Fixes Applied

In
[Setup-Workstation.ps1](file:///C:/usr/src/df/powershell/df-powershell/windows/setup/Setup-Workstation.ps1):

1. **Correct Property Inspection for Account Summary:**

    ```powershell
    [PSCustomObject]@{
        UserName             = $newUser.Name
        FullName             = $newUser.FullName
        AdminGroup           = $adminGroupName
        Enabled              = $newUser.Enabled
        PasswordNeverExpires = ($null -eq $newUser.PasswordExpires)
        AccountNeverExpires  = ($null -eq $newUser.AccountExpires)
    } | Format-List
    ```

2. **Isolated Summary from Group Addition:** Moved the Account Summary display
   outside the group addition `try/catch` block so display logic cannot
   interfere with group assignment reporting.

3. **Graceful Handling of Existing Accounts:** Since user `df` already exists
   from your previous run, re-running the script will detect the existing
   account and prompt:
    ```text
    Do you want to use 'df' and ensure it has Administrator rights? [Y/n]
    ```
    Pressing Enter will skip re-creating the user and display the verified
    account summary cleanly.
